STA-78 · RFC Round: University Crawler v2

RFC-C — Hybrid: deterministic core + gated LLM tail

Revision 5 · 2026-08-23 · 9 universities · 164 programs · 265 cells blind-graded

Revision 5: the fabrication class is closed, and coverage is up to 68%

Revision 3 withdrew the "0 fabrications" headline after the full benchmark found 3 fabrications and 12 wrong values — misattribution on shared pages, invisible to a presence-only provenance gate. Revisions 4 and 5 report the fixes, each closed by a regrade against the same frozen keys: region-scoped harvesting, anchor scope validation, caps-heading anchoring, and banded fee composition. Measured now: 0 fabrications, 5 wrong in 265 cells (1.9%), 243 correct (91.7%), with coverage up from 54% to 68% of all fields.

The more important finding is what the method caught. Hunting these defects surfaced seven further fabrications that no answer key covered — a programme taking its neighbour's degree, another taking an unconfigured section's duration, a master's programme billed at the bachelor's fee. Every one was verbatim-present and gate-clean; none was visible to the benchmark. They were found by reading the provenance of every changed cell, and by a second agent whose only job was to refute the first. Sampled grading measures the pipeline; it does not police it. Attribution review has to be part of the loop.

1 · Recommendation

Build a deterministic extraction core — config-driven anchors, a shared label library, family joins over content-addressed snapshots — with a gated LLM tail for fields the core nulls, behind a mechanical provenance gate. Site knowledge is strictly-validated config data; "can't determine" ships as an honest null. The bet holds: most of this data is extractable deterministically — 8 of 9 universities refresh with zero LLM calls. The correction landed: presence-checking alone was not sufficient; per-program attribution is now a first-class, loader-enforced concern wherever one document serves many programs.

3 · What the full benchmark cycle established

Held up

  • 0 gate failures across 164 programs. No value ever shipped that wasn't in its artifact.
  • Site knowledge really is config. Every fix in the attribution round was generic mechanism (regions, scopes, two label variants) plus config data — no per-site code, under real pressure.
  • Deterministic-first pays. AUBG 90/90 and MUPleven 52/85 with zero LLM calls; refresh is €0 and seconds. Only VUM needs the tail.
  • Honest nulls are real. 48 graded cells are nulls the labeller confirmed as genuinely-absent data, not failures.

Broke — and how it was closed

  • Misattribution on shared pages (3 fabrications, gate-green) → region-scoped harvesting: a program reads only spans anchored to its own name, bounded by siblings and a measured window.
  • Bad anchors can assert → anchor scope validation: every off-page anchor declares names-program (checked at resolve time, base-name aware) or human-attested page-wide; the loader rejects the rest. The fabricating anchor is deleted.
  • Prose mentions opened foreign regions → caps-heading anchoring: on pages with all-caps section headings, only heading occurrences anchor.
  • Stale manual verdicts → verdicts now bind to the shipped value they adjudicated; a changed value returns to CHECK.
  • A rule that was silently inert → the caps-heading rule computed regions on normalised text, where newlines no longer exist, so it never fired in production while its unit tests — which passed raw text — stayed green. Four latent fabrications survived behind it. Its regression test now asserts through the production seam.
  • Partial values are wrong values → a fee order stating one row per year shipped only the first («500 евро»), which the labeller graded WRONG. Joins can now compose the whole schedule.

Sharpened, not confirmed

  • We predicted shared pages were inherently unsafe. ANIS refuted it — all 18 programs on one page, zero contamination, because its statements genuinely are university-wide (now attested as page-wide anchors).
  • The real risk is a shared page carrying program-specific claims — a scope problem with a precise fix, not a reason to avoid shared sources.
  • The benchmark cuts both ways: 2 of the round's "wrongs" were key errors (SU language inferences, UniRuse bizmgmt's formula attributed to the wrong block), each amended with a recorded labeller-confirmed reason.

4 · What remains before this ships

  1. Attribution checking (blocking) — done, measured: fabrications 3 → 0 on the same frozen keys.
  2. Candidate selection — done: heading-anchored regions + label coverage; akusherka's degree now comes from its own section.
  3. Anchor scope validation — done: loader-enforced, with the page-wide escape hatch carrying explicit human attestation.
  4. Finish the wired joins — largely done: a 4-agent config pass won 48 cells (SHU +22, MUPleven +16, UniRuse +7, SU +3). Coverage 54% → 66%; ~45 recoverable cells remain.
  5. Attribution review must stay in the loop — done: written into the process as a third review axis (docs/agents/attribution-review.md), with crawler diff finding the cells. Seven of the fabrications closed in this round sat in cells no answer key covered, so no amount of sampled grading would have found them. The review is now scoped to changed cells rather than graded ones, flags a cell when its status, value, method, artifact or verbatim snippet moved — a value that stays right while its provenance moves is the same defect class, and the value-only ledger diff cannot see it — and requires an independent agent whose only job is to refute the first reading. Honest about its own standing: the loader and the provenance gate are enforced by code, this one by the ticket's done-check.
  6. NBU's fetch route — done, and the premise was wrong. This item read "40 cells are JS-loaded and unreachable without a rendering fallback — an adapter decision, not config." Re-measured: admission is served by a sibling e-catalog tab (P_Menu=admission), plain server-rendered HTML, HTTP 200 — the config had sources {} and no anchors, so it was never fetched. adm_page plus two shared label patterns took NBU from 20/100 to 39/100 fields and 16/25 to 20/25 graded, with no browser, no new dependency and 0 gate failures. The lesson is the same one §3 records: "unreachable" was an inference from an absent value, and nobody had checked it against the site.
  7. NBU's 5 duration cells are a key question, not a config one. The frozen key expects «8 семестъра» for all five sampled programmes; «семестъра» appears on none of their server-rendered pages, and exactly one of NBU's 20 programmes states a duration at all. A human browser can count semesters on the programme-schema tab, but counting is an inference and ADR-0002 forbids shipping it. Logged as benchmark-integrity, awaiting a labeller ruling — NBU's honest ceiling on the current key is 20/25.
  8. Then the attention ledger and refresh orchestrator (ADR-0005) — done: crawler refresh / attention / resolve, with a live tick green over all 10 configs. The first real tick opened three genuine items — UniRuse blocked on a year-lag the site owns (resolved: pointer moved after a byte-identical value check, reason recorded in tracked attention/resolutions.jsonl), VUM blocked because a deterministic tick nulls its 36 tail cells (lapsed when a --tail tick promoted — ADR-0001's no-LLM default doing its job visibly), and SofiaUniversity's 16 unreviewed proposals — since worked through crawler resolve: 12 stale, 3 rejected (2 facultative modules, 1 master's index page), 1 promoted as su-bin (+3 shipped values, attribution-reviewed). Exit is non-zero only on NEW work, so weekly cron + exit code is the whole v1 alerting story; ops doc at docs/operations.md.

5 · What would change my mind

Resolved since rev.1: the JS-heavy bet (AUBG extracted 20/20 with no browser), PDF accuracy (MUPleven 100% on PDF-fed fields), and now the attribution question — rev.3's open flip condition ("if attribution proves impossible deterministically…") did not fire: regions, scopes and heading anchors are all deterministic, and the regrade proves they work.

Still open: if the recoverable-miss backlog (§4.4) keeps regrowing faster than config work closes it as universities are added, the per-program recipe model needs revisiting — that is a scaling question, not a correctness one.

The honest bottom line: a mechanical presence check is a real and rare guarantee — the previous attempt shipped 36% unsupported values, this ships none. Presence was never the same thing as correctness; it took the blind benchmark to measure the difference, three structural fixes to close it, and the same frozen keys to prove it closed. Every defect was found by human labels; every fix is verified by them.
