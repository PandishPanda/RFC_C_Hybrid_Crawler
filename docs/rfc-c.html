STA-78 · RFC Round: University Crawler v2

RFC-C — Hybrid: deterministic core + gated LLM tail

Revision 3 · 2026-08-22 · 8 universities · 148 programs · 190 cells blind-graded

⚠ Revision 3 withdraws revision 2's headline claim

Revisions 1 and 2 led with “0 fabrications”. Across 190 graded cells that was true. Extending the benchmark to all eight universities broke it: 3 fabrications and 12 wrong values, concentrated in one failure mode the earlier samples never touched — misattribution on shared pages, where a program ships a neighbour's value. The value is verbatim in the artifact, so the provenance gate passes it.

The gate's actual guarantee is narrower than we stated: it has never shipped a value absent from its source. It cannot verify that the value belongs to the program it was attached to, and now we have measured what that costs.

1 · Recommendation

Build a deterministic extraction core — config-driven anchors, a shared label library, family joins over content-addressed snapshots — with a gated LLM tail for fields the core nulls, behind a mechanical provenance gate. Site knowledge is strictly-validated config data; "can't determine" ships as an honest null. The bet still holds: most of this data is extractable deterministically, and 2 of 8 universities need no LLM calls at all. The correction: presence-checking is necessary but not sufficient — a per-program attribution check is required wherever one document serves many programs, and that is not optional work.

3 · What the benchmark actually found

Held up

  • 0 gate failures across 148 programs. No value ever shipped that wasn't in its artifact.
  • Site knowledge really is config. Every defect fixed in this round was JSON plus two generic label patterns — no per-site code, under real pressure.
  • Deterministic-first pays. AUBG 90/90 and MUPleven 52/85 with zero LLM calls; refresh is €0 and seconds.
  • Honest nulls are real. 39 graded cells are nulls the labeller confirmed as genuinely-absent data, not failures.

Broke

  • Misattribution on shared pages. MUVarna: two programs shipped an identical degree lifted from a third. UniRuse: two bachelor programs shipped an identical master's degree. Gate-green throughout.
  • Bad anchors can assert. One fabrication came from an anchor aimed at an unrelated project page.
  • First-match selection. Where a page states two competing values, the cascade takes the first — 4 wrongs at ANIS alone.
  • The scorecard itself had two silent defects, including a row hardcoded to PENDING that could never measure.

Sharpened, not confirmed

  • We predicted shared pages were inherently unsafe. ANIS refuted it — all 18 programs on one page, zero contamination, because its statements genuinely are university-wide.
  • The real risk is a shared page carrying program-specific claims. That is a scope problem, and a far more precise fix than avoiding shared sources.
  • NBU's "JS blocks everything" was overstated by half: duration and admission are lost to JS; language and tuition simply aren't published.

4 · What must change before this ships

  1. Attribution checking (blocking). Where one document serves many programs, a value must be bound to its program — proximity to the program's own heading/section, not first match in the document. This is the only defect producing wrong data today.
  2. Candidate selection. When a source states several competing values, choose deliberately (most specific, or the one in the program's own section) rather than first-wins.
  3. Anchor scope validation. An anchor pointing at a page unrelated to the program should fail loudly at config-load, not ship a plausible value.
  4. Finish the wired joins. 50 of 190 graded cells are misses — overwhelmingly programs added without fee/admission recipes. Unglamorous, and the single biggest coverage win available.
  5. Then the attention ledger and refresh orchestrator (ADR-0005), which make the pipeline unattended. Deferred deliberately: surfacing backlog matters less than not shipping wrong values.

5 · What would change my mind

Resolved since rev.1: the JS-heavy bet (AUBG extracted 20/20 with no browser) and PDF accuracy (MUPleven 100% on PDF-fed fields). Both were named as flip conditions; neither fired.

Still open: if attribution checking proves impossible to do deterministically on shared pages, then those universities need LLM-assisted extraction behind the same gate — and the deterministic-first ordering is wrong for roughly a third of the target set.

The honest bottom line: the architecture's trust story is sound but was oversold. A mechanical presence check is a real and rare guarantee — the previous attempt shipped 36% unsupported values and this ships none. It is not the same thing as correctness, and only the blind benchmark ever caught the difference. Every defect in section 3 was found by human labels, none by the pipeline's own checks.
